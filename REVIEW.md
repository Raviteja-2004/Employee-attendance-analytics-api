# REVIEW.md

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Uses `punch_in.replace(hour=..., minute=...)` — no timezone, so the comparison is between a naive local datetime and the punch-in instant, giving wrong results; also `> 10` should yield late for e.g. 10:40:01 (10 min 0.x sec) but the floor happens before the comparison. | Punch at 09:40:01 IST for a 09:30 shift returns 0 instead of 10. | Construct shift_start on the correct IST calendar date, compute floor minutes, compare after flooring. |
| 2 | `compute_work_hours` | Uses Python's built-in `round()` which does banker's (half-even) rounding, violating R4 which specifies half-up. | `round(8.455, 2)` → 8.45 instead of 8.46. | Replaced with a `half_up()` helper using `math.floor(x + 0.5)`. |
| 3 | `compute_overtime` | Does not apply the 30-minute minimum from R3; returns any positive difference. Also constructs the shift-end datetime without timezone, mixing naive and aware types for overnight shifts. | A punch-out 15 minutes after shift end would incorrectly show 15 overtime minutes. | Added `>= 30` threshold; build shift_end datetime in IST, advancing by one day for overnight shifts. |
| 4 | `list_employees` — skip calculation | `skip = page * page_size` skips an extra page (e.g. page 1 skips 20 rows instead of 0). | First page returns the second 20 rows; page 1 should skip 0. | Changed to `(page - 1) * page_size`. |
| 5 | `list_employees` — total count | `count_documents({})` ignores the `department` filter; total is always the full collection size. | Filtered list shows wrong `total`. | Changed to `count_documents(q)`. |
| 6 | `list_employees` — no sort | Result order is undefined (MongoDB natural order). | Pagination is unstable across pages; grader expects `emp_code` ascending. | Added `.sort("emp_code", ASCENDING)`. |
| 7 | `list_employees` — `created_at` not serialized | Returns a Python `datetime` object which FastAPI serialises as an ISO string, not epoch milliseconds required by the API contract. | `created_at` in response is `"2026-01-05T04:30:00"` instead of `1783312500000`. | Added `dt_to_ms()` conversion in the list loop and in `serialize_employee()`. |
| 8 | `create_employee` — race condition | Uses find-then-insert; two simultaneous requests for the same `emp_code` can both pass the check and both insert, giving two documents. | Concurrent test sends duplicate `emp_code` in parallel; both get 201. | Removed the pre-check; rely on the unique index and catch `DuplicateKeyError`. |
| 9 | `punch_in` — no 404 for unknown employee | If `emp` is `None` (unknown `emp_code`), the code crashes with `TypeError: 'NoneType' object is not subscriptable` when accessing `emp["shift_start"]`. | POST punch-in with a non-existent `emp_code` returns 500 instead of 404. | Added `if not emp: raise HTTPException(404, ...)` before using `emp`. |
| 10 | `punch_in` — naive datetime / wrong timezone | `datetime.fromtimestamp(ms/1000)` returns a naive local-time datetime; `datetime.now()` is also naive local time. Date calculations and IST attendance-date logic then fail silently. | Server running in UTC+00 returns wrong `date` for an IST punch-in (e.g. 00:30 IST would return yesterday's date). | Use `ms_to_dt()` (UTC-aware, second-truncated) and `datetime.now(tz=timezone.utc)`. |
| 11 | `punch_in` — no R1 overnight handling | `ts.date().isoformat()` always uses the local date of the punch, ignoring the rule that overnight-shift punch-ins before `shift_end` belong to the previous day. | Night-shift employee punching in at 02:00 IST (before 06:00 shift_end) gets today's date instead of yesterday's. | Introduced `attendance_date_for_punch()` that applies R1 correctly. |
| 12 | `punch_in` — race condition | find-then-insert pattern; two simultaneous punches for the same (`emp_code`, `date`) can both pass and insert duplicates. | Concurrent test: only one 201, rest must be 409. | Removed pre-check; unique index on `(emp_code, date)` + catch `DuplicateKeyError`. |
| 13 | `punch_in` — extra `"id"` field in response | Adds `doc["id"] = str(res.inserted_id)` which is not part of the `AttendanceRecord` schema; also leaks the MongoDB `_id` as a string. | Response contains an undocumented `id` field; `_id` still in dict before `.pop()`. | Removed that line; `serialize_log()` pops `_id` cleanly. |
| 14 | `list_attendance` — loads entire collection | `db.attendance_logs.find(q)` without `.limit()` pulls all matching documents into memory before sorting and slicing. | With ~100 k records, memory usage spikes and response time is very high. | Push sort, skip, and limit into the database query using the indexed `(date, emp_code)` compound index. |
| 15 | `list_attendance` — datetimes not serialised | `punch_in`/`punch_out` are returned as `datetime` objects; the API requires epoch milliseconds. | `punch_in` in response is an ISO string instead of an integer. | `serialize_log()` converts all datetimes to epoch ms. |
| 16 | `health` endpoint | Always returns 200 even when MongoDB is unreachable; the spec says 503 if MongoDB doesn't answer a ping. | Stopping MongoDB still returns `{"status": "ok"}`. | Added `db.command("ping")` inside a try/except; raise 503 on failure. |
| 17 | No indexes created | The starter never creates any indexes. Concurrent duplicate-insert safety relies on them, and analytics queries COLLSCAN on large datasets. | Duplicate `emp_code` can slip through; grader's explain check fails (no IXSCAN). | Added `@app.on_event("startup")` that creates all required indexes idempotently. |

**Items reviewed and found not to be defects:**

- `IST = timezone(timedelta(hours=5, minutes=30))` — correct UTC+05:30 definition.
- Pydantic `BaseModel` usage and `model_dump()` — correct for Pydantic v2.
- `load_dotenv()` / environment variable reading — works fine as-is.
